## 1. Обзор проекта

Разработка SDK для доступа к OpenWeatherMap API, позволяющего разработчикам легко получать данные о погоде для заданной локации.

## 4. Анализ режимов работы SDK

### 4.1 On-Demand Mode

**Описание:** SDK обновляет данные только по запросу клиента.

**Преимущества:**
- Экономия ресурсов (CPU, network)
- Простота реализации
- Предсказуемое поведение

**Недостатки:**
- Возможна задержка при первом запросе
- Зависимость от доступности API в момент запроса

**Сценарии использования:**
- Нечастые запросы погоды
- Ограниченный трафик
- Приложения с низкой нагрузкой

### 4.2 Polling Mode

**Описание:** SDK периодически обновляет данные для всех сохраненных локаций.

**Преимущества:**
- Нулевая задержка для клиента (данные уже в кэше)
- Актуальные данные всегда готовы
- Лучший UX

**Недостатки:**
- Повышенное потребление ресурсов
- Дополнительные запросы к API (может влиять на лимиты)
- Сложность реализации (управление потоками)

**Сценарии использования:**
- Частые запросы погоды
- Real-time приложения
- Dashboard-ы и мониторинг

## 5. Анализ кэширования

### 5.1 Стратегия кэширования

**Выбор:** LRU (Least Recently Used) Cache

**Обоснование:**
- Автоматическое удаление наименее используемых записей
- Оптимальное использование памяти
- Стандартная реализация в Java (LinkedHashMap)

### 5.2 Параметры кэша

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Max size | 10 городов | Требование спецификации |
| TTL | 10 минут | Требование спецификации |
| Eviction policy | LRU | Оптимальная стратегия для данного случая |

### 5.3 Валидация кэша

```
Данные считаются актуальными если:
  current_time - cache_timestamp < 10 minutes

Данные должны обновляться если:
  1. Записи нет в кэше
  2. TTL истек
  3. Принудительный refresh
```

## 6. Анализ обработки ошибок

### 6.1 Типы ошибок

| Категория | Примеры | Обработка |
|-----------|---------|-----------|
| Сетевые | Timeout, Connection refused | Retry + Exception |
| API | Invalid API key, Rate limit | Exception с деталями |
| Валидация | Пустое имя города | IllegalArgumentException |
| Парсинг | Некорректный JSON | Exception с деталями |
| Внутренние | Ошибки кэша, threading | RuntimeException |

### 6.2 Стратегия обработки

1. **Валидация входных данных** - на уровне API
2. **Try-catch блоки** - для внешних вызовов
3. **Custom exceptions** - для специфичных ошибок SDK
4. **Логирование** - всех ошибок для отладки
5. **Graceful degradation** - где возможно

## 8. Анализ паттерна Singleton с несколькими ключами

### 8.1 Проблема

Требуется:
- Поддержка нескольких API ключей
- Невозможность создания двух экземпляров с одним ключом
- Возможность удаления экземпляра

### 8.2 Решение

**Паттерн:** Registry of Singletons (Multiton)

**Реализация:**
```
Map<String, WeatherSDK> instances = new ConcurrentHashMap<>();

getInstance(apiKey):
  if (instances.containsKey(apiKey)):
    return instances.get(apiKey)
  else:
    create new instance
    store in map
    return instance

removeInstance(apiKey):
  shutdown polling if active
  remove from map
```

## 9. Риски и ограничения

### 9.1 Риски

| ID | Риск | Вероятность | Влияние | Митigation |
|----|------|-------------|---------|------------|
| R-001 | Rate limiting OpenWeatherMap API | Высокая | Высокое | Мониторинг лимитов, backoff strategy |
| R-002 | Проблемы с многопоточностью в polling mode | Средняя | Высокое | Thread-safe коллекции, тщательное тестирование |
| R-003 | Утечка памяти в кэше | Низкая | Среднее | Использование WeakReferences, мониторинг |
| R-004 | Изменения в API OpenWeatherMap | Низкая | Высокое | Версионирование, абстракция API клиента |

### 9.2 Ограничения

- **API Limits:** Free tier - 60 calls/minute, 1,000,000 calls/month
- **Network:** Зависимость от сетевой доступности
- **Memory:** Ограничение на 10 городов в кэше
- **Polling frequency:** Минимум 10 минут (TTL кэша)
